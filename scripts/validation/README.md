# Verification selection

`plan.mjs` selects current GPUI + Wry checks by changed paths. Documentation selects link/whitespace checks. Renderer changes select static and component tests. Shared contracts, native code and toolchain inputs select a compiled candidate, contracts and real packaged startup. Unknown paths select complete verification. Deleted and renamed paths participate in selection.

Bundled files under `resources/skills/` and `resources/code-cli-skills/`, including Markdown/text, and `packages/provider-registry/data/providers.json` are generated Go inputs. They select generation through build, Go consumers, desktop tests and native contracts. Development skill documentation remains documentation-only. Plans naming test projects must select the `ts` task; toolchain flags are validated against the selected tasks before CI uses them.

The root commands are implemented in [../desktop](../desktop/README.md). Both Windows workflows retain manual dispatch. Only `desktop-build.yml` additionally accepts pushes to the exact `GPT/GPUI` experiment branch, so its actual Windows candidate is built, tested and packaged automatically. Other automatic triggers remain rejected. The selected plan is a JSON file; cross-job outputs contain boolean flags rather than path lists or reasons. Missing/invalid plan files fail verification. There is one current product target, no compatibility application, no installation in Git hooks and no public-package release policy gate.
