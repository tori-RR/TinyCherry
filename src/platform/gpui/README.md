# GPUI / Wry transport

Installs the desktop API before the React application loads. Wry's `window.ipc.postMessage` carries JSON requests to the GPUI host; `window.__TINYCHERRY_RECEIVE__` receives correlated replies and events. The bridge limits each request to less than 4 MiB and 128 in-flight requests, applies a 60-second deadline, and rejects outstanding work on page unload. A random per-document session prevents replies from a previous page settling requests after a reload. Requests and mutations are never replayed automatically.

The transport retains subscription cleanup, binary DTO conversion, message projection leases and terminal backend-loss handling. Only the top-level packaged page (`http://tauri.localhost` / `tauri://localhost`) or the compiled-in fixed development origin may install it. The host independently checks the sender origin and command envelope. This origin check establishes the app boundary; business and computer-control authorization remain in the existing host/backend routes.

The packaged origin deliberately retains its existing name for WebView2 storage compatibility. Together with the unchanged `evostack-data/webview` profile directory, it keeps `localStorage['cs_cache_persist']` readable across the host migration. Its current schema contains 51 UI-state keys, including open/pinned/active tabs, recent conversations, composer input history, pane sizes, group expansion, recent emoji and settings-page filters. Renaming the origin would initialize a separate store with defaults. `http://tinycherry.localhost` and `tinycherry://localhost` are therefore rejected instead of becoming a second release origin. The retained protocol name does not load or expose Tauri; desktop requests use only the GPUI/Wry bridge above. A future origin rename requires an explicit storage migration.
